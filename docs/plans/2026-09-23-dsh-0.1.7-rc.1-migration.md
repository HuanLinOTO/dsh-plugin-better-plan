## 本插件触点分析（rg 全量扫描，排除 node_modules/lib/dist/docs 与 *.md）

| Touchpoint | Hit | File/line | Card | 结论 |
|---|---:|---|---|---|
| #1 patch | 否 | — | — | bundle 形态，无 DSH 源码 patch |
| #2 events | **是** | `src/index.ts:117`（`agent/session-start` 订阅）；`tests/composition.spec.ts:151-152` | RC1-07 | 迁移到 `agent/created` |
| #3 services/Remote | 部分 | `src/client/execution-launch.ts`（`ctx.get('sessions'/'workspaces')` 结构化 face） | RC1-33 | 未使用被删方法，见下 |
| #4 filesystem | 是 | `src/index.ts`（计划文件 stat/read）、`src/resolve-cwd.ts` | — | 与本次卡片无关 |
| #5 UI/commands/tools | 是 | `src/shadow-tool.ts`（`defineTool`/`ToolDefinition`）、`src/client/index.tsx`（better-sidebar tab） | — | 契约未变 |
| #6 custom channel | 是 | `src/ws-route.ts`、`src/review-route.ts`（`webServer.registerUpgrade/register`） | — | 信任栅栏自管，卡片未触及 |
| #7 subprocess | 否 | — | — | 无 |

- **RC1-07 命中**：`src/index.ts` 的遮蔽挂接原订阅 `agent/session-start`（事件在 0.1.7 被删除，监听器永不触发 → `exit_plan_mode` 不再被遮蔽）。迁移到 `agent/created`，payload 为 `{ agent, source, signal? }`；该事件为串行派发（监听器抛错会拒绝创建），故监听器保持同步、幂等（per-agent `WeakSet`），显式返回 `undefined`。测试同步改为 `agents.enter` + `await agents.announce(agent, 'startup')`（0.1.7 `announce` 需显式 `source`），并删除手工 `agentEvents(...).emit('agent/session-start', …)`。
- **RC1-26 非命中**：`IconPlanOutline16` 是本插件 `src/client/icons.tsx` 自绘的内联 SVG（非 `ui-primitives` 导出），名称巧合，`ui-primitives` 图标重命名不影响。
- **RC1-33 非命中（有保留）**：`execution-launch.ts` 走的是 `ctx.get('sessions')`/`ctx.get('workspaces')` 的**结构化自述 face**（`create`/`binding().session.prompt`/`open`/`list.getSnapshot`），并非被 RC1-33 改动的 `WorkspaceBrowserInjected`（`renameSession/forkSession/archiveSession` 移除、`requestSessionRename`/`createWorkspace` 新增）。故本卡不触发源码改动；仅保留运行时验证依赖。
- **RC1-29 非命中**：本插件不注册 DSH 右栏 `plan` tab，而是经 better-sidebar 自有服务开「Plan」tab；`ui-plan` 是附加包，不冲突，也不改变遮蔽后的工具契约。
- **RC1-04/27 非命中**：`planDir`/`maxPlanBytes`/`locale` 是 composition-only 配置（无设置页、无 `.volatile()` 需求），无 `settings.register`、无 `settingsScope`。

## 行动

1. **RC1-01**：`package.json` 的 7 个 `@deepseek-ai/dsh-*` peer `^0.1.5-rc.1` → `^0.1.7-rc.1`；`@deepseek-ai/cordis`（`^4.0.1`）、`dsh-better-sidebar`（`^0.17.1`）、react/schemastery 不动。
2. **RC1-07**：
   - `src/index.ts`：`ctx.on('agent/session-start', …)` → `ctx.on('agent/created', …)`，监听器显式 `: undefined` 返回（0.1.7 串行派发要求 `undefined | Promise<undefined>`）；更新模块注释。
   - `src/context.ts`：注释里的事件名同步为 `agent/created`。
   - `tests/composition.spec.ts`：`announce(agent)` → `await announce(agent, 'startup')`，去掉手工 `agent/session-start` emit。
   - `cordis.patch.yml`、`AGENTS.md`：机制注释里的 `agent/session-start` → `agent/created`。

## 实际结果（2026-09-23 执行记录）

- **registry 0.1.7 静态校验**：`tsconfig.rc1.json`（host+tests+client）与 `tsconfig.client.rc1.json`（纯 client）**均零错误**。
- **测试**：`pnpm test` 14 文件 / 136 用例 **全绿**（对当前 checkout 0.1.5-rc.2+139，该 checkout 已同时具备 `agent/created` 与旧 `announce` 重载，故运行时断言成立）。
- **构建**：`pnpm run build` ✅，`lib/index.js`、`lib/types/{index,context}.d.ts` 重建；client bundle 内容不变。
- **对当前 checkout 的 `pnpm typecheck`**：**红 1 处** — `tests/composition.spec.ts(151,44) error TS2554: Expected 1 arguments, but got 2`。这是**过渡态**：0.1.5-rc.2 checkout 的 `announce(agent)` 仍是单参，而 0.1.7-rc.1 要求 `announce(agent, source)`；本地类型源在 checkout 升级到 0.1.7 后即转绿（registry 校验已证 0.1.7 下正确）。属版本跳变的预期差异，非逻辑回归。
- **改动文件**：`src/index.ts`、`src/context.ts`、`tests/composition.spec.ts`、`package.json`、`cordis.patch.yml`、`AGENTS.md` + 预构建 `lib/`。工作区 link 路径未变；未提交。

## pending / 残余风险

- 真实 0.1.7 host 上的运行时挂载未验证（本批统一 registry 静态校验 + 当前 checkout 单测）：遮蔽注册、`agent/created` 串行派发下 `agent.ctx.effect` 的注册时机、以及 delegation 的 `ctx.sessions`/`ctx.workspaces` 结构 face 需在 0.1.7 实机冒烟。
- RC1-33 的结构 face（`sessions.create(opts)`、`binding(id).session.prompt`、`workspaces.list`）未在上游 0.1.7 类型树中显式校验（本插件刻意不 import，保持纯度门）；若上游改了 session/workspace controller 契约，需实机发现。已保留运行时验证依赖。
